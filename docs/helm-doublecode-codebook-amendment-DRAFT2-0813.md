## 1 · THE ONE CODEBOOK

> ### **STEP 0 — THE GATE. Ask first, of every row: is this a codable defect claim in the row's own voice at all? A row that does not, in its own voice, name a specific faulty thing AND the way it failed, with the fault INSTANTIATED, is `EXCLUDED`, and no class test is run on it.**
> ### **STEP 1 — THE LADDER. A row that passes the gate takes the FIRST specific class whose sufficiency test fires on the row's own quoted text, in the fixed precedence of §4.**
> ### **STEP 2 — THE RESIDUAL. `OTHER` is written for a gated-in row on which ALL FOUR tests fail. NOTHING LEAVES `OTHER` AFTERWARDS — there is no later section, sub-rule or genre list that may take a row out of the residual.**

`EXCLUDED` is a **gate**, not a residual. `OTHER` is a **residual**, not a gate. DRAFT 1
had them the other way round in half its text, and that is the whole of the structural
defect. The gate answers *"is there a defect here to code?"*; the ladder answers *"which
kind?"*; the residual holds *"a real defect of a kind we have not enumerated"* — the closure
law applied to our own taxonomy. **A residual is what is left after the tests run.** It is
not a verdict a coder may reach before running them, and it is not the place a hard row goes.

### 1.1 · The pipeline, in the order a coder runs it — the ONLY pipeline in this file

```
  for each row:

    1. THE LADDER (§4 precedence, tests at §1.2). Run tests 1..4 IN ORDER; the FIRST that

    2. THE RESIDUAL. No test fired -> OTHER. TERMINAL.
```

### 1.2 · The four sufficiency tests, in the fixed order they are applied

| # | Class | Fires when the row, in its own text, exhibits… |
|---|---|---|
| 1 | `statement-level-type-traps` | a formal object the toolchain ACCEPTS whose written form says something weaker, emptier, or other than the claim it is taken to make |
| 2 | `misattributed-mechanisms` | a phenomenon + a cause already on the record for it + a reading in the SAME row showing that named cause is not the operative one |
| 3 | `stale-citations` | a named concrete referent that a still-standing artifact was asserting or relying on AFTER that referent had moved |
| 4 | `wrong-scope-on-a-measured-claim` | a standing measured sentence whose named object, population or time-window is wider than or different from the one actually measured |

*The order is not arbitrary and it is not a tie-break of convenience — it is derived in §4
from what the row's own correction must TOUCH: a kernel-checked statement, then the causal
story, then the referenced object, then the claim's boundary.*

### 1.3 · THE CONSISTENCY CLAUSE — why gate-first can never lose a real defect

⛔ **The gate is strictly WEAKER than every sufficiency test.** *Each of the four tests, to
fire at all, requires the row to exhibit a faulty thing (a statement, a cause, a citation, a
claim) and the way it failed (accepted-yet-wrong, non-operative, moved, over-named). Any row
on which a test fires therefore passes the gate by construction. **If a coder believes a
test fires on a row they gated out, the gate was misapplied — re-run the gate, do not
override it.** This clause is what makes "gate first" and "test first" the same answer on
every row where they could disagree, and it is the reason the gate may be stated once and
never revisited.*

### 1.4 · The blinding constraint (binding on the gate AND on every test)

⛔ **Every test and the gate must be satisfiable FROM THE ROW ALONE.** *The coder may not
grep the bus, `git log`, `git show` or diff around a row to establish a prong — those are how
the other coder's reasoning reaches this one. **If a test needs evidence the row does not
carry, the test does not fire; if the gate needs evidence the row does not carry, the gate
does not open.***

### 2.2(a) · **EXHIBITS vs CITES — THE OPERATIVE TEST** *(RATIFIED 2026-08-14, sitting ruling 1 of 10; the Captain's word)*


LOCATION rather than a COUNT.

## 4 · PRECEDENCE AMONG THE SPECIFIC CLASSES

> **RULE — Ask what the row's own correction must change, and file the row at the FIRST class whose test fires on the post's text, in this fixed order: (1) a formal statement, type, predicate, instance, or acceptance criterion that the intended object fails or an unintended object satisfies → `statement-level-type-traps`; (2) an effect both readings agree occurred, credited to the wrong agent, command, process, or mechanism → `misattributed-mechanisms`; (3) a cited commit, file, quote, or premise whose content moved after it was cited → `stale-citations`; (4) otherwise, a finding that stands with only its stated range, level, or domain wrong → `wrong-scope-on-a-measured-claim`.**

**RATIONALE.** The four specific classes are not siblings — **they are ordered by what the
repair has to touch:** a kernel-checked statement, then the causal story, then the referenced
object, then the claim's boundary. `wrong-scope-on-a-measured-claim` is by its own definition
the residual *among the specifics*, so it must sit last and can never win a row where a deeper
test fires — exactly the axis the two coders split on, since pass 1 used `wrong-scope` as its
within-taxonomy catch-all (13 of 21 rows) while pass 2 named the deeper class. **Each test
must actually FIRE on quoted content — plausibility is not enough.**

⛔ **THE WINNING CLASS MAY LIE OUTSIDE THE DISPUTED PAIR.** *The ladder is run over the row,
not over the disagreement. DRAFT 1's coverage claim measured which SIDE of a disputed pair a
row falls on; a pass-3 coder picks a CLASS from five, with no pair in front of them. Worked
instances from the refuter's unnamed-row sample: **275** → `misattributed` (neither coder),
**75501** → `type-traps` (neither coder), **5893** → `wrong-scope` after test 3's temporal
clause declines it, **45252** → `EXCLUDED` (neither coder). Class-determinacy was audited in
