THE HAND-CUT SIGNATURE, measured on the real caller before writing the rule:
```
bitserial_switch declares  input : rst_n act_stb sel_stb in0 in1 clk
                           output: out0 out1
the caller passes          --inputs  … act0 act1 sel0 sel1   ← 4, all WIRE
                           --outputs out0,out1,_00_.._03_    ← 4, all WIRE
⇒ EQUAL COUNTS OF NON-PORT NETS ON BOTH SIDES, ALL DECLARED `wire`.
  That is the cut: Q nets read as inputs, D nets written as outputs, paired
  by position — precisely what the flop treatment now does automatically.
```
THE RULE (narrowest form that admits the honest caller):
  an --outputs name that is NOT a declared output is ACCEPTED iff
    (a) it is a declared NET (wire) in the module, AND
    (b) the caller is performing a SYMMETRIC hand cut: the count of --inputs
        names that are not declared inputs EQUALS the count of --outputs names
        that are not declared outputs, and both are > 0, and all are wires.
  Anything else still REFUSES.

WHAT THE RULE DELIBERATELY STILL CATCHES — the teeth must survive:
  * a FABRICATED name (declared nowhere) — refuses; it is not a wire.
  * an INPUT passed as an output — refuses; it is declared `input`, not `wire`.
  * a wire named as an output with NO matching input-side cut — refuses;
    clause (b) fails, so a lone stray wire cannot slip through.
