WHAT CHANGES — the narrowest rule that makes the refusal principled:
  W1  In the netlist bit-select path (import_netlist.py ~:728-743): when a base
      name IS a declared vector, require lo <= idx <= hi. Out of range = HARD
      ERROR naming the declared bounds and the offending index.
  W2  In the --inputs path: the same check for caller-supplied `base[idx]`
      entries. Case C enters here, so W1 alone would not close it — "everywhere"
      is the ruling's word and it means both doors.
  ⛔ DELIBERATELY NOT CHANGED: the ESCAPED-name path (`\regs[20] [26]`). Those
      names are not declared vectors and reach the same code; the check applies
      ONLY when the base is in vector_ports. Whether an escaped bit-select must
      be a declared vector is a DIFFERENT question and is not this ruling's.
