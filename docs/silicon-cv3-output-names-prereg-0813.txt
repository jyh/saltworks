SCOPE — the SAFE HALF ONLY, and the other half is named as a policy question:
  ✅ DO:   every name in --outputs must be DECLARED AS AN OUTPUT by the module.
           A name that is not a declared output is a HARD ERROR. This catches a
           typo, a wire mistaken for a port, and an input passed as an output.
  ⛔ DO NOT: refuse when a DECLARED output is OMITTED from --outputs. A caller
           may legitimately import a sub-cone. Whether an omitted output should
           refuse, warn, or pass is a POLICY CALL and is not mine to make inside
           a soundness fix. Flagged, not taken.

WHY IT IS THE SAME FAMILY AS C-V1/C-V2: those guard the INPUT side — a vector
passed by base name (C-V1) and a bit index outside the declared range (C-V2).
The OUTPUT side has no guard at all, and its failure is worse to read: the datum
records `outs` as NET INDICES IN DECLARATION ORDER, so a wrong name silently
shifts every downstream index and the datum proves theorems about the wrong
signal while importing clean and reading back green.
